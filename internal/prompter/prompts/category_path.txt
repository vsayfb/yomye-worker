Place a requested or offered service written in any language into one stable, reusable global category hierarchy.

Yövmiye providers may be individuals, tradespeople, teams, shops, or small businesses. Categories
describe what service is offered or sought; they do not imply a provider type.

Canonical category metadata is always English. Detect the source text's locale and also return
presentation metadata in that source language.

Current active hierarchy:
%s

Return valid JSON only:
{
  "source_locale": "tr",
  "category_path": [
    {
      "canonical_name": "",
      "canonical_slug": "",
      "canonical_description": "",
      "localized_name": "",
      "localized_slug": "",
      "localized_description": "",
      "locale": "tr",
      "is_selectable": false
    }
  ]
}

Rules:
- Detect source_locale as a lowercase BCP-47 language tag such as tr, en, or de.
- Every node's locale must equal source_locale.
- canonical_name and canonical_description must be concise, natural English.
- canonical_slug must be a lowercase ASCII slug derived from canonical_name.
- localized fields must be natural in source_locale; localized_slug derives from localized_name.
- Reuse an existing canonical path, with its exact canonical metadata, whenever it reasonably
  describes the same concept, regardless of the input language.
- Create a new node only when no existing sibling represents the same general concept.
- A category represents a reusable service, trade, or occupation—not the wording, symptom, individual
  task, employer, or one-off request in the listing.
- Determine the hierarchy from the actual occupation or product domain, not from generic verbs
  such as repair, manage, support, build, sell, or work.
- A root must be a coherent long-lived sector. Do not use broad cross-sector catch-alls such as
  "İş ve Profesyonel Hizmetler" or activity labels such as "Bakım ve Onarım".
- An intermediate node must be a recognized subdomain, not a sentence or description.
- The leaf must be the smallest reusable service, trade, or occupation explicitly supported by
  the input, not a particular task and not an invented combination of related services.
- Prefer provider-neutral service concepts when the input names a service or business activity.
  Use "Car Wash", not "Car Wash Specialist"; "Computer Repair", not "Computer Repair Expert".
  Keep established occupational names when the concept is inherently a role, such as "Lawyer",
  "Plumber", or "Graphic Designer".
- Do not add person-role suffixes such as Specialist, Expert, Professional, Technician, or their
  localized equivalents merely to make a service sound like a profession.
- Do not broaden the input by adding adjacent services or specializations. For example, Turkish
  "Oto Yıkama" resolves to canonical "Car Wash" and localized "Oto Yıkama"—not "Car Wash and
  Auto Detailing Specialist". Create or reuse "Auto Detailing" only when detailing is explicit.
- Do not narrow the input to a specialization that is only implied or commonly associated.
- Set is_selectable=true for every node that is itself an actual reusable service, trade, or
  occupation a user or listing may reference.
- Set is_selectable=false only for organizational/grouping nodes that must never be selected.
- Selectability is independent of hierarchy: a selectable service or occupation may have more
  specific selectable concepts beneath it. Never infer selectability from depth or child presence.
- The final node must always have is_selectable=true.
- Order nodes from broad domain to specific category.
- Prefer 2 or 3 meaningful levels; never return more than 4.
- Avoid redundant levels and nodes with nearly identical meanings.
- Never create a distinct canonical concept merely because the source language or translated
  wording differs. Lawyer, Avukat, and Rechtsanwalt are the same canonical concept.
- A genuinely reusable specialization may be a child concept, such as Immigration Lawyer under Lawyer.
- Use natural localized occupational terminology, never literal word-for-word inventions.
- Existing categories are suggestions, not authority: never reuse an existing path whose parent
  is semantically wrong for the requested occupation or product.
- Do not use "Diğer", "Genel", or catch-all categories when a meaningful category is possible.
- Do not force a listing into the current hierarchy when it genuinely belongs to a missing branch.
